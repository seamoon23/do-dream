## 3. 리소스 관리

### 리소스 타입
- 링크
- 메모
- 파일
- 코드
- 프롬프트
- 스크린샷/이미지 메모

### 파일 리소스 MVP 정책
- 파일명, MIME 타입, 크기, 등록일 저장
- 사용자가 직접 요약 입력
- 파일 자체 저장은 선택 기능
- 텍스트 계열 파일은 본문 저장 허용
- PDF/Docx는 자동 파싱하지 않고 요약/태그 입력으로 대체

### 리소스 필드
- 제목
- 타입
- URL
- 파일명
- 요약
- 태그
- 중요도
- 검토 상태: `미검토`, `유효`, `부족`, `폐기`
- 연결된 단계 ID

## 4. 실행 가능성 검토

### 점수 항목
각 항목 1~5점.

| 항목 | 설명 |
|---|---|
| 문제 명확성 | 무엇을 해결하는지 명확한가 |
| 사용자 가치 | 실제 사용할 이유가 충분한가 |
| 구현 난이도 | 오늘/이번 주 안에 만들 수 있는가 |
| 리소스 충분도 | 참고자료, 요구사항, 예시, 파일이 충분한가 |
| 기술 적합성 | 현재 기술 스택으로 가능한가 |
| 확장 가능성 | MVP 이후 확장 여지가 있는가 |
| 수익/활용 가능성 | 광고, 판매, 업무 활용 가능성이 있는가 |
| 리스크 | 법률, 보안, 유지보수 리스크가 낮은가 |

### 자동 판정
- 평균 4.0 이상: 실행 추천
- 평균 3.0 이상: 보완 후 실행
- 평균 3.0 미만: 보류 추천

### 부족 리소스 자동 표시
점수가 낮은 항목에 따라 필요한 리소스 체크리스트를 제안한다.

예:
- 문제 명확성 낮음 → 사용자 시나리오, 핵심 문제 3개 필요
- 구현 난이도 낮음 → 기술 검증 Todo 필요
- 리소스 충분도 낮음 → 참고 링크/첨부/예시 화면 필요
